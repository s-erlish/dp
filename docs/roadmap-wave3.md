**Дата:** 2026-07-09.

**Не дублирует** уже существующие доки. Опирается на:

## 1. Полная русификация UI

**Цель.** Довести русскую локаль до 100 %: ни одной английской строки в пользовательском UI при
системном языке `ru`. Приложение по умолчанию таргетирует РФ, поэтому это **P0**-гигиена.

**Диагностика (факты, не оценки).** Сравнение ключей `res/values/strings.xml` (525 строк) и
`res/values-ru/strings.xml` (479 строк) даёт **~40 ключей без русского перевода** — все они добавлены
командой в предыдущих волнах и отдают английский текст на ru-устройствах:

```
app_name  auth_account  auth_sign_in_telegram  auth_subscription_active
auth_subscription_active_until  auth_subscription_expired  auth_subscription_none
auto_fallback_switching  browser_dialer_mode  color_theme_blue  color_theme_mono
memory_app_usage  memory_elevated  memory_high  memory_normal  memory_value
menu_item_fast_connect  ping_method_http  ping_method_icmp  ping_method_real  ping_method_tcp
routing_settings_outbound_tag_hint  speed_zero  sub_days_left  sub_expired  sub_expires
sub_pin  sub_support  sub_traffic_unlimited  sub_traffic_used  sub_unpin  sub_website
summary_pref_auto_fallback  summary_pref_show_memory  title_pref_auto_fallback
title_pref_color_theme  title_pref_ping_method  title_pref_show_memory
```

Из них **не требуют перевода** (форматтеры/бренд, `translatable="false"` или уже RU в дефолте):
`app_name`, `sub_days_left` (`%1$s · %2$dd`), `memory_value` (`%1$d МБ · %2$s`), `speed_zero` (`0`),
`auth_sign_in_telegram` (уже «Войти через Telegram» в дефолте). Остальные **~34 ключа — перевести**.

**Захардкоженные латинские строки в разметке/коде (полный список, малый объём):**
- `layout/item_recycler_main.xml:119` — `android:text="JSON"` (метка типа конфига; можно оставить — это тех-термин, но лучше вынести в строку `label_json`).
- `ui/MainActivity.kt:561` — `toast("else")` — отладочный тост в `when`-ветке; заменить на строковый ресурс или убрать.
- `layout/activity_server_vless.xml` — 1 латинская `android:text` (проверить, тех-заголовок).

Прочие экраны (About, диалоги ошибок) наследуют переводы из upstream v2rayNG и в основном покрыты.

**Файлы/классы к правке**
- `res/values-ru/strings.xml` — добавить ~34 недостающих ключа (значения из таблицы ниже).
- `res/values/strings.xml` — при выносе `JSON`/`"else"` добавить новые ключи.
- `res/layout/item_recycler_main.xml:119`, `ui/MainActivity.kt:561` — заменить хардкод на `@string/…` / `getString(…)`.
- (опц.) прочие `values-*` (fa/ar/vi/zh…) — вне scope волны 3, отметить как долг.

**Приёмочные критерии**
- `comm -23` ключей `values/` и `values-ru/` (за вычетом `translatable="false"`) → пусто.
- На эмуляторе с локалью `ru` визуально пройдены: Хоум, Серверы, Настройки, мета-бар подписки, RAM-панель, меню fast-connect, тост авто-фолбэка, экран логина/аккаунта — английского текста нет.
- Никаких `toast("…")`/`setText("…")` с латиницей в UI-ветках (grep `setText\("[A-Za-z]`, `toast\("`).
- Lint `MissingTranslation` не растёт (или добавить осознанные `tools:ignore` только для тех-меток).

**Риски.** Длинные RU-строки ломают однострочные метки (щит-статус, чипы) → проверить эллипсис/перенос.
`translatable="false"`-форматтеры не трогать. Плюрализация «дней/серверов» — использовать `plurals`, а не `%d + слово`.

## 2. Онбординг + пустые состояния + прайминг разрешений

**Цель.** Первый запуск без серверов не должен выглядеть «сломанным». Дать короткий Incy-онбординг,
довести пустое состояние до эталонного вида и мягко объяснить разрешение VPN до системного диалога.

**Что уже есть (переиспользовать, не дублировать).**
- Пустое состояние серверов **существует**: `res/layout/layout_servers_empty.xml` (иконка,
  `servers_empty_title`, кнопки «Добавить из буфера» `servers_add_clipboard` + «Сканировать QR»
  `menu_item_scan_qrcode`), включается в `MainActivity.updateServersChrome()` (`ui/MainActivity.kt:326-328`),
  клики привязаны в `setupEmptyState()` (`ui/MainActivity.kt:299-302`) → `importClipboard()`, `importQRcode()`.
- Кит карточек/иконок: `res/drawable/bg_card_incy.xml`, `bg_icon_{blue,green,orange,purple,red,yellow}.xml`.
- Права VPN уже запрашиваются в `startVpnWithPermission()` (в `MainActivity`), запуск — `handleFabAction()` (`:156`).

**Объём волны 3 (три под-задачи).**

**2a. Первый запуск (onboarding).** Лёгкий, 2–3 слайда, БЕЗ тяжёлых зависимостей (ViewPager2 + точки).
Показывать один раз (флаг `PREF_ONBOARDING_SHOWN` в MMKV). Слайды: (1) «Быстро и безопасно» — щит/бренд;
(2) «Добавьте подписку» — как импортировать (буфер/QR/Telegram); (3) «Готово» — кнопка «Начать».
Копирайт — **фактологичный, не рекламный** (юридическая осторожность из `strategy-russia-2026.md §4.1`:
не маркетировать обход блокировок).

**2b. Полировка пустых состояний.** Привести `layout_servers_empty.xml` к Incy: круглая
иконка-плитка на `bg_icon_blue`, заголовок 20sp/600, подзаголовок-подсказка, основная синяя кнопка
«Добавить из буфера», вторичная outlined «Сканировать QR», третья текстовая «Войти через Telegram»
(если бэкенд включён — открывает `LoginActivity`). Пустое состояние Хоума (когда сервер не выбран):
`tv_selected_server` сейчас показывает `title_file_chooser` (`ui/MainActivity.kt:791`) — заменить на
«Сервер не выбран» + подсказку-стрелку на вкладку «Серверы».

**2c. Прайминг разрешений.** Перед системным диалогом VPN (первый `prepare()`), если он ещё не выдавался,
показать Incy-боттомшит: «Разрешение на VPN — Android попросит подтвердить создание VPN-подключения. Мы не
читаем ваш трафик.» Кнопка «Продолжить» → системный диалог. Для Android 13+ аналогично мягко объяснить
POST_NOTIFICATIONS (нужно для закреплённого уведомления) — приоритет ниже.

**Файлы/классы к правке / создать**
- `ui/OnboardingActivity.kt` (**новый**) + `res/layout/activity_onboarding.xml`, `item_onboarding_page.xml`; адаптер ViewPager2.
- `AppConfig.kt` — `PREF_ONBOARDING_SHOWN`, (опц.) `PREF_VPN_PERMISSION_PRIMED`.
- `ui/MainActivity.kt` — в `onCreate` (после `super`, до основной инициализации, ориентир `:126`) проверять флаг и стартовать онбординг; праймер вставить в `handleFabAction()`/`startVpnWithPermission()` (перед `prepare()`).
- `res/layout/layout_servers_empty.xml` — рестайл (2b).
- `ui/MainActivity.kt:788-792` (`updateSelectedServer`) — пустой Хоум-стейт (2c-текст).
- `res/values/strings.xml` + `values-ru/` — `onboarding_*`, `empty_home_no_server`, `perm_vpn_priming_*`.

**UI/UX (Incy).** Фон — тот же полноэкранный градиент, что и на Хоуме. Кнопки — Material3 filled
(brand_blue) + outlined. Никаких стоковых картинок — только векторные иконки из проекта. Боттомшит
праймера — `bg_card_incy` со скруглением сверху.

**Сложность:** M. **Приоритет:** P1.
**Риски.** Не блокировать «power-users», которые вставляют конфиг сразу — онбординг пропускаемый (кнопка
«Пропустить»). Не показывать праймер повторно при отказе бесконечно (одноразовый флаг + повтор только по явному тапу коннекта).

**Приёмочные критерии**
- Первый запуск на чистой установке → онбординг; второй запуск → сразу Хоум.
- Пустой список серверов → Incy-состояние с рабочими кнопками буфер/QR (уже привязаны) + Telegram.
- Перед первым системным VPN-диалогом показывается праймер; «Продолжить» ведёт к системному диалогу; отказ не крашит.
- Онбординг/праймер полностью на русском; фон-градиент совпадает с Хоумом.

## 3. Per-app split tunneling в стиле Incy

**Цель.** Переработать существующий `PerAppProxyActivity` в современный Incy-экран: сгруппированный,
с поиском, иконками приложений и переключателем on/off на каждом приложении, вместо чекбокс-списка.

**Текущее состояние (факты).**
- Экран: `ui/PerAppProxyActivity.kt` (весь файл, 322 строки), адаптер `ui/PerAppProxyAdapter.kt`,
  строка списка `res/layout/item_recycler_bypass_list.xml` (иконка `@+id/icon` + `AppCompatCheckBox` на `:40`),
  экран `res/layout/activity_bypass_list.xml`. VM: `viewmodel/PerAppProxyViewModel.kt`.
- Загрузка приложений: `util/AppManagerUtil.loadNetworkAppList()` (только приложения с интернет-permission).
- Модель выбора: множество пакетов в MMKV (`PREF_PER_APP_PROXY_SET`), режим blacklist/whitelist —
  `switchBypassApps` (`PREF_BYPASS_APPS`), общий тумблер `switchPerAppProxy` (`PREF_PER_APP_PROXY`).
- Изменение выбора требует рестарта сервиса: `SettingsChangeManager.makeRestartService()` (`:241`).
- Тулбар-меню (`menu_bypass_list`): поиск (`SearchView`), выбрать всё, инверсия, авто-выбор
  (`ANDROID_PACKAGE_NAME_LIST_URL`), импорт/экспорт буфера.

**Редизайн Incy (что именно менять).**
1. **Строка приложения** (`item_recycler_bypass_list.xml`): слева — иконка приложения в скруглённой
   плитке (радиус как у флаг-плитки серверов), по центру — имя (15sp/500) + package (12sp,
   `colorOnSurfaceVariant`), справа — Material3 `SwitchMaterial` (iOS-подобный, тот же стиль, что в
   ките настроек) вместо чекбокса. Высота строки ≥ 56dp, таргет ≥ 48dp.
2. **Хедер экрана** в стиле Incy-настроек: карточка `bg_card_incy` с двумя рядами — «Split tunneling»
   (общий тумблер) и «Режим: маршрутизировать выбранные / исключить выбранные» (сегмент/переключатель
   `switchBypassApps`), с пояснением-подписью вместо тоста-«info».
3. **Группировка**: два раздела с заголовками-стикки — «Пользовательские» и «Системные»
   (`AppInfo.isSystemApp`), выбранные приложения — вверху (сортировка уже есть в `initList()`, `:79-95`).
   Опционально счётчик «Выбрано: N» в подзаголовке хедера.
4. **Поиск**: перенести из тулбар-`SearchView` в постоянное Incy-поле поиска под хедером (как на
   вкладке «Серверы»), логика `filterProxyApp()` (`:294-316`) переиспользуется; убрать пересоздание
   адаптера на каждый ввод — заменить на `submitList`/фильтр во ViewModel (см. риски).
5. **Мгновенное применение**: тумблер на строке → `viewModel.toggle(pkg)` + `makeRestartService()`
   (как сейчас в `allowPerAppProxy()`), без «сохранить». Показать снэкбар «Изменения применятся при переподключении».
6. Действия «выбрать всё/инверсия/авто/импорт/экспорт» — из тулбар-меню в компактное меню-«⋯» в хедере.

**Файлы/классы к правке**
- `res/layout/item_recycler_bypass_list.xml` — чекбокс → `SwitchMaterial`, плитка иконки, двухстрочный текст.
- `res/layout/activity_bypass_list.xml` — Incy-хедер-карточка + постоянное поле поиска + sticky-заголовки.
- `ui/PerAppProxyAdapter.kt` — переход на `ListAdapter`/`DiffUtil`, биндинг свитча, sticky-секции (или два вьютайпа: header/app).
- `ui/PerAppProxyActivity.kt` — вынести фильтрацию во ViewModel; убрать пересоздание адаптера (`:312-313`); привязать хедер-тумблеры и меню.
- `viewmodel/PerAppProxyViewModel.kt` — добавить `filter(query)`/`LiveData<List<AppInfo>>` со стабильными id.
- (переиспользовать) `res/drawable/bg_card_incy.xml`, `bg_icon_*`, стиль свитча из кита настроек.

**UI/UX (Incy).** Тёмный фон, карточки скруглены, синий акцент только на активных свитчах; иконки
приложений — оригинальные (`AppInfo.appIcon`). Плейсхолдер загрузки — короткий шиммер/прогресс
(`showLoading()` уже есть).

**Сложность:** M–L (L из-за sticky-секций + миграции адаптера на DiffUtil). **Приоритет:** P2.
**Риски.**
- **Производительность/память**: `PerAppProxyAdapter(apps, …)` пересоздаётся на каждый символ поиска
  (`:312-313`) — на устройствах со 150+ приложений это дёргает GC (перекликается с дисциплиной ОЗУ,
  `master-requirements-audit §13b`). DiffUtil обязателен.
- Иконки приложений тяжёлые в памяти — грузить лениво/через кэш, не держать полный список Drawable.
- Смена режима blacklist↔whitelist инвертирует смысл выбора — не потерять текущий набор (сохранять сырой набор пакетов, а не «включён/выключен»).
- Требуется рестарт активного соединения — честно предупреждать снэкбаром.

**Приёмочные критерии**
- Экран показывает приложения с иконками, свитчем on/off, разбивкой Пользовательские/Системные, выбранные — сверху.
- Поиск фильтрует без заметных лагов и без пересоздания адаптера; прокрутка плавная на 150+ приложениях.
- Переключение приложения мгновенно пишет в набор и триггерит рестарт при активном соединении.
- Режим «маршрутизировать/исключить» и общий тумблер работают как раньше; импорт/экспорт буфера сохранены.
- Экран полностью на русском, визуально согласован с вкладкой «Настройки».

## 4. Суточная статистика трафика (по дням, ↑/↓)

**Цель.** Копить и показывать трафик по дням (отдельно отдано/принято) с минимальной нагрузкой на
память и без тяжёлого хранилища.

**Точка интеграции (уже существует).**
`handler/NotificationManager.kt`, метод сбора статистики (`:244-284`) каждые `QUERY_INTERVAL_MS`
опрашивает `CoreServiceManager.queryAllOutboundTrafficStats()` и уже вычисляет **дельты** трафика:
`proxyUplink` / `proxyDownlink` (`:239-260`) перед отправкой `MSG_STATE_SPEED_UPDATE` (`:270`). Это
идеальное место для аккумуляции суточных сумм — дельты уже посчитаны, дополнительных запросов к ядру не нужно.

**Модель хранения (лёгкая, не БД).**
- Ключ-«бакет» на день: `traffic_YYYYMMDD` в отдельном MMKV-инстансе (`MMKV.mmkvWithID("daily_traffic")`),
  значение — упакованные два `long` (up, down) или маленький JSON `{u,d}`.
- Инкремент в `NotificationManager`: `today = todayKey(); addDelta(today, upDelta, downDelta)` —
  read-modify-write двух long. Частота записи высокая (каждые ~2 c при трафике) → **буферизовать в
  памяти** (`AtomicLong upAccum/downAccum` + текущий день) и **флашить в MMKV** раз в N секунд / при
  остановке сервиса / при смене дня, чтобы не долбить диск.
- **Ретеншн**: хранить последние **30 дней**; при флаше удалять ключи старше 30 дней (дешёвый префикс-скан).
  Итого ≤ 30 маленьких записей — память/диск пренебрежимы (перекликается с дисциплиной ОЗУ, аудит §13b).
- Смена суток: детектировать по изменению `todayKey()` в цикле опроса; при пересечении полуночи
  зафиксировать остаток в старый день, начать новый бакет.

**Отображение (Incy).**

  без внешних чарт-библиотек — экономия памяти и размера APK). Кнопка «Сбросить статистику».

**Файлы/классы к правке / создать**

- `handler/DailyTrafficManager.kt` (**новый**) — MMKV-бакеты, буфер+флаш, ретеншн 30 дней, API `getLastDays(n)`, `reset()`, `todayUpDown()`.

**Сложность:** M. **Приоритет:** P2.
**Риски.**

## 6. Анти-DPI улучшения под РКН (июль 2026), реально поддержанные Xray-core

**Цель.** Усилить выживаемость под TSPU/DPI **только реалистичными** средствами, которые Xray-core в
этом форке уже умеет: тюнинг Fragment, политика uTLS/Reality, дисциплина Mux, и активная liveness-перепроверка
(«TLS-freeze» детект → фолбэк). Опирается на `docs/strategy-russia-2026.md` (§1 landscape, §3 стратегия)
и `docs/circumvention-settings-design.md`; здесь — **точки интеграции в конфиг-билдер**, не повтор стратегии.

**Ключевая точка интеграции конфиг-билдера.**
`core/CoreOutboundBuilder.kt`:
- `updateOutboundTls`-ветка (`:560-583`) строит `TlsSettingsBean` (`serverName`, `fingerprint`, `alpn`,
  reality-поля `publicKey/shortId/spiderX/mldsa65Verify`) и присваивает `tlsSettings` (TLS) или
  `realitySettings` (REALITY).
- `updateOutboundFragment()` (`:594-670`) — уже собирает `fragment`-маску (packets/length/interval,
  дефолты `tlshello`/`50-100`/`10-20`, для REALITY packets→`1-3`) и `noise`-маску для UDP; берёт значения
  из `PREF_FRAGMENT_*`.
- Прочие prefs: `PREF_MUX_*` (`AppConfig.kt:38-41`), `PREF_FRAGMENT_*` (`:42-45`).

Всё поле для тюнинга уже есть в модели (`dto/V2rayConfig.kt`, `dto/entities/ProfileItem.kt`:
`flow`, `security`, `fingerPrint`, `realitySettings`). **Новых протоколов не нужно.**

**Реалистичные под-задачи (что именно делать).**

**6a. «Russia mode» — один переключатель дефолтов (S–M).** Пресет, который при включении задаёт
безопасные под-TSPU дефолты, не трогая пользовательские конфиги руками:
- `PREF_FRAGMENT_ENABLED = true` + пресет «Aggressive DPI» (ClientHello-split): для TLS `packets=tlshello`,
  для REALITY `1-3` (логика уже в `:608-618`); при желании чуть более агрессивные `length/interval`.
- Гарантия непустого браузерного `fingerprint` (uTLS): если у ноды `fingerPrint` пуст — подставлять
  `chrome` перед построением `TlsSettingsBean` (`:564`). Пустой SNI/fingerprint под РФ — прямой флаг (§1.2, §3.3).
- `PREF_MUX_ENABLED = false` для Reality/Vision (Vision сам мультиплексирует; Mux вредит — §3.2).
- **Валидация операторских шаблонов**: предупреждать, если locked-sub отдаёт пустой/явно фейковый SNI
  для REALITY (интеграция с `hidden-templates`), но не переопределять операторский `dest` без спроса.
- **Не включать ECH** под РФ-таргеты по умолчанию (`echConfigList` оставлять пустым — пара
  `cloudflare-ech.com`+ECH-расширение сама триггерит блок, §1.7).

**6b. uTLS enforcement + опц. ротация (S).** В `updateOutboundTls` (`:564`) — если `fingerprint` пуст
и включён Russia mode, ставить дефолт (chrome); опционально рандомизация профиля из набора
{chrome, firefox, safari, random} на соединение. Никаких пустых/экзотических JA3.

**6c. Fragment auto-tune под «freeze» (S).** Оставить существующую маску, но вынести пресеты в
Russia mode и (опц.) чуть увеличить агрессивность split для REALITY. Значения по-прежнему из `PREF_FRAGMENT_*`,
чтобы power-user мог переопределить. Не менять формат `finalmask` (`:642-664`).

**6d. Liveness re-check / «TLS-freeze» детект → авто-фолбэк (M).** Самое ценное. РКН-«заморозка»
(≈25 пакетов / ~16 КБ, затем тихий стоп без RST — §1.3) проходит TCP-пинг, но убивает сессию. В проекте
уже есть: одноразовый post-connect health-check (`ui/MainActivity.kt:231-246`, `delayResultAction` →
`fastConnect(excludeGuid=…)`), авто-фолбэк (`PREF_AUTO_FALLBACK`) и методы пинга (`enums/PingMethod.kt`,
включая `ping_method_real`). Волна 3:
- **Периодическая** (не только одноразовая) лёгкая проверка живости во время соединения: маленький
  запрос к нейтральной цели через тоннель; если стынет/таймаут — триггерить тот же авто-фолбэк-путь.
- Проверка должна **пробивать порог 16 КБ** (реальная нагрузка, а не TCP-пинг), иначе «замёрзшая» нода
  выглядит живой (§2 #11, `ping_method_real`). Ранжировать кандидатов по реальной достижимости.
- Батарея: интервал 30–60 с, увеличивать при стабильности, «липкий успех» — не дёргать при рабочей ноде
  (переиспользовать логику `scheduleHealthCheckIfEnabled`, `ui/MainActivity.kt:818+`).
- Гейтить одним флагом (`PREF_LIVENESS_RECHECK`), не ломать текущую однократную проверку.

**Что НЕ делать в волне 3 (нереалистично/за рамками ядра сейчас):** AmneziaWG (нет в форке — только
WireGuard), полноценный kill-switch (отдельная задача `strategy §2 #8`), новые UDP-протоколы. Отметить как долг.

**Файлы/классы к правке / создать**
- `core/CoreOutboundBuilder.kt:560-583` (uTLS/SNI enforcement) и `:594-670` (fragment-пресеты) — читать Russia-mode флаг.
- `AppConfig.kt` — `PREF_RUSSIA_MODE`, `PREF_LIVENESS_RECHECK`, (опц.) `PREF_UTLS_FINGERPRINT`.
- `handler/SpeedtestManager.kt` — реальный >16 КБ тест для ранжирования (расширение метода `ping_method_real`).
- `ui/MainActivity.kt:818+` (`scheduleHealthCheckIfEnabled`) — сделать периодическим при включённом liveness.
- (валидация) `handler/AngConfigManager`/hidden-templates — предупреждение о пустом SNI/fingerprint.
- Настройки: ряд «Режим Россия» в ките настроек (P1) + подпись-пояснение (фактологично, не рекламно — §4.1 стратегии).
- `res/values(-ru)/strings.xml` — `russia_mode_*`, `liveness_recheck_*`.

**UI/UX (Incy).** Один заметный ряд «Режим Россия» в «Настройки → Соединение» с оранжевой/синей
иконкой (`bg_icon_*`) и коротким честным пояснением. Никакого языка «обход блокировок» в сторе/копирайте.

**Сложность:** M (6d — основная часть; 6a–6c — S каждая). **Приоритет:** P1 (выживаемость).
**Риски.**
- Переопределение операторских настроек может **сломать** рабочую ноду — Russia mode задаёт дефолты
  только там, где поле пусто; операторский `dest`/`serverName` не трогать без явного согласия.
- Периодический liveness-тест = трафик + батарея; строго гейтить и «липкий успех».
- Разделяемый канал `MSG_MEASURE_DELAY` с ручным тест-тапом (известный MEDIUM из `review-04`) — не
  усугублять: liveness должен использовать отдельный канал/тег результата.
- Fragment/uTLS — «community-proven», но не гарантия; копирайт честный (нет «непробиваемого» протокола, §вводная стратегии).
- Не включать ECH под РФ по умолчанию.

**Приёмочные критерии**
- Включение «Режим Россия» на ноде с пустым fingerprint → в собранном конфиге непустой браузерный
  `fingerprint`, `fragment` включён с корректной маской, Mux выключен для Reality (проверка через лог/дамп конфига).
- Операторский непустой SNI/fingerprint НЕ перезаписывается; предупреждение при пустом SNI для REALITY.
- При искусственной «заморозке» соединения периодический liveness детектит стоп и триггерит авто-фолбэк
  на рабочую ноду в пределах интервала; TCP-«живая-но-мёртвая» нода ранжируется ниже.
- ECH по умолчанию выключен под РФ-таргеты; всё UI на русском; нет регрессий в обычном (не-Russia) режиме.
