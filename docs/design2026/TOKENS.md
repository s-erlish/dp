# Токены редизайна — что заведено и как этим пользоваться

Результат волны фундамента (README §1, §6, §8). Всё перечисленное **уже в репозитории и собирается**.
Ссылайтесь на эти имена; заводить свои дубликаты нельзя — второй набор имён на то же самое и есть
то, ради чего фундамент делался первым.

## Цвет

Новый атрибут `?attr/colorPressBg` — шаг фона под нажатием (тёмная `#0D1017`, моно `#0B0B0C`,
светлая `#EAEFF7`). Плюс `@color/select_item_selected`.

Остальные цвета §8 **уже имели имена**, дубликатов не заведено: `#20242B` = `colorSurfaceContainerHighest`,
`#2A2E36` = `colorOutline`, `#141619` = `colorSurface`, `#1A1D21` = `colorSurfaceContainerHigh`,
`#9BA1AD` = `colorOnSurfaceVariant`, `#17325C`/`#CFE0FF` = пара primaryContainer,
`#3A2E00`/`#EAB308` = `chip_json_*`.

## Отклик на нажатие

В разметке:

```xml
android:background="@drawable/bg_row"
android:stateListAnimator="@anim/press_row"
```

Аниматоры: `press_row` (строка, карточка) · `press_button` (кнопка, чип, пункт окошка) ·
`press_icon` (иконка без фона) · `press_connect` (кнопка подключения).

**Для всего, внутри чего есть текст, предпочтительнее из Kotlin:**

```kotlin
view.pressFeedback(R.anim.press_row)
```

Это тот же аниматор плюс аппаратный слой на время анимации — лечение грабли №1 (текст дёргается
при возврате). В разметке этого не выразить.

Ripple выключен по всему продукту одной строкой: `colorControlHighlight` прозрачный в `AppThemeBase`
и в оверлее диалогов. **Но** около шестидесяти `?attr/selectableItemBackground` остались в разметках
экранов — фундамент их не трогал, потому что это чужие файлы. Ничего не светится, однако **шаг фона
под нажатием появится только когда владелец экрана поменяет фон на `@drawable/bg_row`.** Это ваша
работа на своём участке.

## Окошко выбора — `com.v2ray.ang.ui.component.SelectPopup`

Заменяет одиночный `AlertDialog`. Не пишите свой второй.

```kotlin
SelectPopup.show(
    anchor = binding.rowDns,          // строка, к которой подвешено
    options = names.toList(),
    selectedIndex = idx,
    widthRes = R.dimen.select_popup_w_dns,
    valueView = binding.valueDns,     // гаснет пока открыто, необязательный
    caret = binding.caretDns,         // поворачивается на 180°, необязательный
) { picked -> apply(picked) }
```

Закрывается сам. `onPick` не срабатывает при повторном выборе текущего значения и при отмене.
Уже подключён к **Режиму** в `SettingsTabFragment.pickMode()` как доказательство работоспособности —
намеренно без правки разметки, чтобы не столкнуться с волной Настроек.

Ширины: `select_popup_w_mode` 176 · `_dns` 210 · `_ping` 208 · `_appearance` 186 · `_language` 166 ·
`_interval` 176 · `_default` 200.

Реализовано всё, чего требует §6: литой фон `colorSurfaceContainerHighest`, radius 16, обводка 1dp
`colorOutline`, elevation 20; привязка top 48 / right 8 с перепривязкой на каждом pre-draw, чтобы
прокрутка его не отрывала; раскрытие срезом сверху вниз 260 мс плюс прозрачность 180 мс, **без
масштаба**; открытая строка поднимается над соседями через elevation с обнулённым outline provider,
чтобы подъём стоил Z-порядка, а не тени; `clipChildren`/`clipToPadding` сняты вплоть до корня
содержимого; открыто всегда одно; закрывается по нажатию вне и по «назад»; выбранный пункт
объявляется TalkBack.

Готово, но никем не используется: `bg_row_top` / `bg_row_bottom` / `bg_row_only` со скруглением 19dp —
для карточки, которая больше не обрезает детей.

## Находки в прототипе для владельцев экранов

Фундамент их увидел, но не стал трогать чужое:

- **Плитки строк настроек в прототипе нейтральные**, а в репозитории `bg_icon_blue`, `bg_icon_orange`
  и прочие. Менять через `?attr/iconTileBg*`, не зашитым цветом.
- **Строка настроек в прототипе `padding 10×16`**, в репозитории `space_12`.
- **Значение в строке выбора в покое — полной яркости `colorOnSurface`**, в репозитории приглушённое.
  `SelectPopup` намеренно возвращает строке тот цвет, который у неё был, а не навязывает яркий.
- **Каретка.** §6 даёт строке выбора каретку, а в репозитории `ic_chevron_right`. Нужный
  `ic_arrow_drop_down` уже существует ровно с путём из прототипа (`M7,10l5,5 5,-5z`) — это замена
  одного атрибута, но её делает владелец Настроек, чтобы одна строка не отличалась от соседних.

## Расхождения, оставленные владельцу на решение

- **`radius_chip` 12 → 8 противоречит `CLAUDE.md`**, где 12 закреплено. §8 говорит 8; прежняя
  двенадцатка живёт дальше как `radius_tile`. Строка в `CLAUDE.md` устарела и исправлена.
- **Выбранный пункт окошка.** README: «фон на шаг выше». В прототипе он окрашен так же, как тело
  окошка, в обеих темах — то есть никакого шага там нет и галочка остаётся единственной пометкой.
  Сделано по README.
- **Кривая возврата.** README §1/§8 дают `.34,1.25,.64,1`; прототип использует `.34,1.2,.64,1` на
  строках и пунктах и `1.25` на кнопках и иконках. Взято README-шное 1.25 везде.
- **Направление шага фона.** Существующий код шагал вверх, §1 и §8 требуют вниз, к `#0D1017`.
  Заведена новая роль, а не перенаправлена старая — чтобы ничей цвет не поменялся молча.
