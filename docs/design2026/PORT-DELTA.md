# Часть 3. Конфликты и вопросы

## Конфликты «1:1 сломает работающее»

**К1. Радиус кнопок: 24–26dp (пилюля) против 16dp (прямоугольник).**
README §2 и §5 требуют пилюль (radius 24–26dp, 48–52dp). `values/dimens.xml` фиксирует
`radius_button = 16dp` с записью: *«D-6: buttons are a 16dp rounded RECTANGLE, not a pill. This
supersedes 00-rules.md 3.2's "buttons are pill" on the owner's recorded rejection of capsule CTAs»*.
То есть капсульные CTA владелец однажды уже отверг. Нельзя молча выбрать одно из двух.

**К2. Бюджет акцента.** `CLAUDE.md` и `00-rules.md 3.6`: одна залитая акцентная поверхность на
экран. В прототипе главной их две — тональная «Поддержка» в карточке подписки и акцентная заливка
выбранной строки сервера; на аккаунте — залитый переключатель автопродления плюс акцентное кольцо.
Формально это нарушение действующего правила репозитория.

**К3. Пилюля состояния на главной.** README §4 требует пилюлю в трёх состояниях, включая
«Не подключено». Владелец 2026-08-03 велел убрать слово «Отключено» из этой зоны, и `fragment_home.xml:470-492`
это фиксирует: пилюля — подтверждение успеха, а не поле статуса. Прототип — новее, но
формулировка прямо противоположная. Нужно слово владельца.

**К4. Подэкран «Постоянный VPN» с двумя переключателями.** Android **не даёт приложению** включать
always-on VPN и блокировку трафика без VPN — это системные настройки, приложение может только
открыть `Settings.ACTION_VPN_SETTINGS` (что сборка и делает). Перенос «1:1» даст два переключателя,
которые ничего не переключают. Сноска самого прототипа это признаёт: «Оба переключателя живут в
настройках Android — кнопка ниже откроет их напрямую». Переносить как **два индикатора состояния**
(read-only) или не переносить вовсе.

**К5. «Режим»: два варианта против трёх.** См. П-25. README §6 отдаёт «Режиму» два значения,
в сборке их три, и третье владелец назвал сам.

**К6. Экраны прогрузки против экрана входа.** См. П-13. §3 описывает вход как оверлей; в сборке это
`LoginActivity` с e-mail, OTP, 2FA и Google. Оверлей должен встать **поверх** реальных состояний
`AuthViewModel`, а таймингов 1200 / 3000 / 4600 мс в реальности не существует — шаги меняются по
ответу сервера. Переносить надо **вид**, а тайминги использовать только как потолки анимации.

**К7. Шрифт.** README §8: «гротеск для заголовков, Roboto для текста». В сборке заголовки —
`@font/golos_text_bold`, текст — `@font/golos_text_regular`, а Space Grotesk остался только для
`Display`, `Chip`, `Numeric` и вордмарка. Причина записана в `values/styles.xml` и
`activity_base.xml`: **у Space Grotesk ноль кодпоинтов в U+0400–U+04FF**, русский заголовок в нём
рисуется подставным шрифтом. Прототип пишет русские заголовки Space Grotesk'ом только потому, что
браузер молча подставляет системный шрифт. Возврат к «гротеску для заголовков» = возврат бага M-36.
Roboto в проекте не вендорен вообще.

**К8. Отклик у строк: масштаб против шага фона.** README §1 требует масштаба 0.975 у строк списка.
`values/styles.xml` (`Widget.Departament.Row`) и `drawable/bg_row.xml` явно запрещают масштаб у
строк: *«scaling a row tears the hairlines above and below it»*. Кроме того, README требует шаг фона
**вниз** (`--pressBg #0D1017`), а `bg_row.xml` делает шаг **вверх** (`colorSurfaceContainerHigh
#1A1D21`). Два решения в противоположные стороны.

**К9. Светлая тема.** См. П-24. Все числа §8 даны для тёмной и моно. Любое зашитое `#…` в разметке
сломает светлую тему, которая в сборке живая и переключается.

## Расхождения внутри пакета

**Р1. Лестница нажатия.** README §1 — 0.975 / 0.965 / 0.88 / 0.97 при 70 / 200 мс с отскоком;
`project_rules.md` — 0.98 / 0.96 / 0.94 / 0.90 при 90 / 160 мс. Уже зафиксировано в
`ЧИТАТЬ-ПЕРВЫМ.md` §2. Добавлю: **числа `project_rules.md` — это ровно то, что стоит в
`values/motion.xml` сейчас**, то есть `project_rules.md` описывает сборку, а README — новое
требование.

**Р2. Кривая возврата.** README §1 и §8 дают `cubic-bezier(.34, 1.25, .64, 1)`, а
